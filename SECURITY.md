# Security and responsible disclosure

We welcome responsible reports concerning this repository and its published tools.

If GitHub's private vulnerability-reporting feature is available, use the repository's Security tab to report sensitive issues privately. If it is unavailable, open a minimal issue asking maintainers for a private reporting channel; do not include exploit details, credentials, private data or other sensitive information in the public issue.

For ordinary reliability, documentation, research or reproducibility errors, use the public issue tracker.

Test only systems and data that you are authorised to test. Do not access accounts, customer data, or infrastructure outside the scope of permission. Prefer local fixtures and minimal reproductions. Describe the affected version, observed impact and proposed mitigation. Do not publish sensitive technical details before coordinated disclosure.

This policy does not grant authorisation to test any third-party product or live Primitive Labs service.
